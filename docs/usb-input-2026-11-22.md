# USB 输入设备：四台设备的真相（2026-11-22）

**结论先写**：guest 能枚举的输入设备**不止两台**。现在跑着的机器上有四台：

```
hengevm: xhci: the guest addressed device 0 (slot 1, port 1)   ← 键盘 05ac:0220
hengevm: xhci: the guest addressed device 1 (slot 2, port 2)   ← 触控板 05ac:0265 (MT2)
hengevm: xhci: the guest addressed device 2 (slot 4, port 3)   ← 平板 QEMU usb-tablet（绝对坐标）
hengevm: xhci: the guest addressed device 3 (slot 3, port 4)   ← 鼠标 QEMU usb-mouse（相对）
```

## 之前为什么"只认两台"

不是 macOS 限制，也不是 device tree 声明（`HV_DT_DUMP` 出来的 ADT 里**只有** `port-virtual-1` / `usb-device`，那是 restore 用的虚拟口，**没有任何 xHCI 端口/设备节点**；xHCI 是 PCI 功能，设备靠普通 USB 枚举）。

真正原因是**我们报错了端口速率**：

--- 现场 ---
设备描述符 `bcdUSB 0x0200` = High-Speed 设备（触控板/平板/鼠标都是），
而 `reset()` 里把端口速率写成 `(p ? SPEED_HIGH : SPEED_FULL)`，第三台之后一律 Full Speed。
macOS 的 AppleUSBXHCI 遇到"端口速率与设备不符"会**重置整个控制器**，
于是所有设备一起消失 —— 看起来就像"guest 完全不枚举"。

--- 修法 ---
```c
static uint32_t port_speed(int port) {
    const uint8_t *d = devs[port].device_desc;
    return d && d[2] == 0x00 && d[3] == 0x02 ? SPEED_HIGH : SPEED_FULL;   /* bcdUSB 0x0200 */
}
```
修完：第三台（平板）立刻枚举，第四台（鼠标）也立刻枚举。

**教训**：`portsc` 里的 speed 位不是装饰，报错会让 macOS 把整条总线重置；
"全灭"要优先怀疑控制器侧的状态，不要归因于 guest 的模型。

## 第二个关键发现：设备 ID 必须是 Apple 的

四台设备都 `ADDRESS` 成功之后，只有触控板走完了枚举：

```
dev 1 触控板: … → GET_DESCRIPTOR 0x22（报告描述符）→ CONFIGURE ENDPOINTS ✅
dev 0/2/3:    … → SET_CONFIGURATION → SET_INTERFACE → ✗ 结束
```

用 QEMU 的 ID（`0627:0001` 鼠标、`1b36:0001` 平板）时，macOS 走到 `SET_INTERFACE` 就放弃，
**不读报告描述符、不 CONFIGURE ENDPOINTS**，于是报告排了队也没人取。

换成 **Apple 自己在 Virtualization.framework 里用的 ID** 后立刻全部通过：

| 设备 | ID | 结果 |
|---|---|---|
| 平板 | **`05ac:8106`** "Virtual USB Tablet"（VZ 自己就提供这个设备） | CONFIGURE ENDPOINTS ✅ |
| 鼠标 | **`05ac:0304`** Apple Optical USB Mouse | CONFIGURE ENDPOINTS ✅ |
| 键盘 | `05ac:0220`（本来就是 Apple） | CONFIGURE ENDPOINTS ✅ |
| 触控板 | `05ac:0265`（本来就是 Apple） | CONFIGURE ENDPOINTS ✅ |

结论：**macOS guest 的 USB HID 栈只对 Apple 的设备 ID 完成配置**（QEMU 的通用 ID 停在
`SET_INTERFACE` 之后）。这也是为什么 Apple 自己的 macOS VM 只给 Mac 键盘 + Mac 触控板。

## 设备与用途

| 设备 | 描述符来源 | 谁在用 |
|---|---|---|
| `05ac:0220` 键盘 | Apple（macOS 自带驱动，无需 Keyboard Setup Assistant） | 物理键盘、屏幕控制键、输入法逐键 |
| `05ac:0265` MT2 触控板 | Apple（10 指、8134×5206 传感器） | 鼠标模式（相对）、两指手势 |
| `usb-tablet` | QEMU `hw/usb/dev-hid.c`（GPL-2.0-or-later，逐字复制描述符；接口协议 **0x00**，usage Mouse） | 触控模式（绝对，"点哪打哪"） |
| `usb-mouse` | QEMU `hw/usb/dev-hid.c` | 蓝牙/USB 鼠标（相对、真 1/2/3 键、真滚轮） |

## Android 侧的混合事件处理（查文档后的结论）

1. **指针捕获后 source 变成 `SOURCE_MOUSE_RELATIVE`（0x20004）**，按 `SOURCE_MOUSE` 判断会漏掉 → 全部被当手指处理。判断要加：
   ```java
   (source & SOURCE_MOUSE_RELATIVE) == SOURCE_MOUSE_RELATIVE
   || e.getToolType(0) == TOOL_TYPE_MOUSE
   ```
2. **相对位移是批处理的**：官方文档要求消费全部样本（`getHistoricalX/Y` 再 `getX/Y`），否则指针一顿一顿、走不远。
3. **`ACTION_CAPTURE_LOST`（隐藏常量 0x4000）**：指针离开窗口时系统收回捕获，要立刻重取，否则系统光标回来、事件全无。
4. **捕获可能"成功但没事件"**：看门狗 2 秒无事件就 `releasePointerCapture()`，退回 hover（实测 hover 一直可用）。
5. **布局必须铺满整块屏幕**（`setDecorFitsSystemWindows(false)` + `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`，不要给 root 加 inset padding）：否则边缘那几条属于系统，指针一走进去就"离开窗口"。
6. 悬浮球是 App 内的独立窗口（`PopupWindow` + `setTouchModal(false)`），它只在自己那块矩形里取事件。
