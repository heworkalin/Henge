# UI 功能归属：每件事只有一个地方能改

## 为什么要这张表

这一轮整理前的实际状态（不是感觉，是 grep 出来的）：

| 设置项 | 可修改的位置 | 后果 |
|---|---|---|
| Vulkan 驱动 | 设置 → 渲染；诊断 → 来源 | 诊断页里选的那个只影响本次探测、不保存，看起来像"设置没生效" |
| 内存 | 设置 → 默认配置；这台 Mac → 设置 | 两处改的是同一个 `Prefs.ramMb`，标签却说是"新机默认"和"下次启动生效" |
| CPU | 同上 | 同上 |
| 进入 guest 画面 | Macs 页 hero 的「启动」；这台 Mac 组的「显示」 | 两个按钮同一动作，用了一个，另一个像是坏的 |
| macOS 磁盘用量 | 设置 → 存储；这台 Mac → 存储 | 同一文件两处展示 |
| IPSW | 这台 Mac → 存储（读 `macOS.ipsw`）；安装页（读真实路径） | `macOS.ipsw` 这个文件名从来没有被创建过，所以那行永远是「无」 |
| 安装映像 | 设置 → 存储（清理）；安装页（导入） | 不是重复：一个导入、一个清理，保留 |

## 现在的归属

**设置（全局，与具体实例无关）**
- 外观：主题、主题色
- 渲染：**驱动（唯一可改点）**
- 显示：控制条自动隐藏
- 存储：安装映像（清理）
- 诊断：设备能力（只读诊断页）、日志
- 权限、关于（含开源许可证页）

**这台 Mac → 设置（属于这台机器）**
- 名称、**内存（唯一可改点）**、**CPU（唯一可改点）**
- 磁盘、辅助存储、IPSW（只读展示，IPSW 显示真实路径/文件名）

**诊断页（只读）**
- 驱动：展示当前引擎会打开的库，并注明"在 设置 → 渲染 中切换"
- 重新测量、原始报告

**Macs 页**
- hero 的「启动」是**唯一**进入 guest 画面的入口
- 「这台 Mac → 设置」进入机器设置
- 「安装 macOS」进入安装页

## 判据（写代码前先过一遍）

```
这个值有没有第二个地方能改？
    有 → 加之前先删掉一个；否则两条路径迟早不一致
这个按钮和别处的按钮做的是同一件事吗？
    是 → 删掉一个，或者合并成一个入口
这一行展示的数据，来源和别处展示的是同一个文件吗？
    是 → 只在一个地方展示；另一个地方给指针（"在 X 中查看"）
```

`Prefs` 里每个 setter 的调用点就是这张表的机器可读版本：

```bash
cd android/app/src/main/java/dev/henge/probe
for k in $(grep -oE 'static void set[A-Za-z]+' Prefs.java | sed 's/static void //'); do
  echo "$k: $(grep -rl "Prefs.$k(" *.java | grep -v Prefs.java | tr '\n' ' ')"
done
```

**每条都应该只有一处**（例外：`setLocalIpsw` 有两处——安装页写入、清理时置空失效路径，
两者不是"两个地方编辑同一个值"）。
