# 回测：667 个页为什么反复 fault（2026-11-17）

## 1. 回测方法与结果

用已有日志做静态回测（不新跑设备），把 16819 次 EL0 故障按 16 KiB 页聚合，再看
**同一页内的 fault 落在哪些偏移**：

| 类别 | 判定标准 | 页数 | 含义 |
|---|---|---|---|
| 正常 page-in | fault 次数少、偏移递进、时间窗窄（span 11–14） | 约 6000 | 首次访问装入，之后不再 fault |
| **反复失败** | ≥5 次 fault，且**只有一个偏移** | 708 页 | 同一地址反复重试，页从未装入 |
| 其中 offset 恰为页首 0x0 | — | **117/117**（runS4 同类集合） | 只碰到页首就持续失败，页内其它字节从未成功访问 |

最典型的样本：

```
0x102614000  faults=136  distinct far=1  distinct pc=9  span #201 -> #16164（横跨全程）
0x1002c0000  faults=126  distinct far=2  pc=13
0xbd2114000  faults=291  distinct far=1  pc=9   （另一个 run）
```

**同一地址、多个不同 pc、跨越整个运行期**：这不是"某段代码重试一次"，而是
**该页在整个运行期间始终没有装入，任何访问它的代码都会 fault**。

## 2. 与"是否已映射"的相关性（实测）

| 页 | fault 次数 | 回查 |
|---|---|---|
| 0x102614000 | 136 | UNMAPPED |
| 0x1002c0000 | 126 | UNMAPPED |
| 0x10030c000 | 123 | UNMAPPED |
| 0x1000f8000 | 119 | UNMAPPED |
| 0x101070000 | 91 | 已映射 0xb4574000 |
| 0x1013a4000 | 8 | 已映射 0xc7fec000 |

结论：**fault 次数与该页是否仍未装入强相关**。

## 3. 必须撤回的一个判断

前一份文档（`vm-layer-vs-pmap-2026-11-17.md`）写过"VM Map 里确实有 entry"，
依据是扫到 `{prev,next,start,end}` 形状的节点。**这个判断是错的**，回测时发现：

1. 已映射的代码页 `0x100f9c000` **找不到任何这样的节点** —— 若它是 vm_map_entry，
   不可能有映射却没有 entry；
2. 节点的 `prev` 指向 `0xfffffe11260bfab0`，而该地址**不在链上**（链是
   `fa60 → fc40 → f880 → fce0 → fc90 → fb50 → …`）—— 真正的双向链表必须互相回指；
3. 每个节点还带 `mach_absolute_time` 形式的时间戳（`57bfe66000000000`）与递增的
   `0x2002b980/0x2002bac0`，更像某种审计/记录数组。

**因此 "VM Map 里有没有这段地址" 目前仍是未知**，不能用那些节点当作证据。
这也解释了为什么按 `task+0x50/+0x58` 找 vm_map 一直失败 —— 结构偏移仍未定。

## 4. 这一轮仍然成立的事实

| 事实 | 依据 |
|---|---|
| 故障是 `translation fault L3`（无 PTE），不是权限/外部 abort | ESR 解码：DFSC=7，EA=0 |
| 引擎 walk 正确 | `hv_walk_dbg` 轨迹与手工遍历一致，L1/L2 有效、L3=0 |
| PTE 没被写到错误物理页 | `HV_SLOW_MEM=1` 下 `TLB-fresh mismatch` = 0（40154 条 store） |
| 反复失败的页不止一个 | 708 页 ≥5 次，117 页全在 offset 0 |
| 不是等磁盘 | ramdisk 在内存，块设备无请求 |

## 5. 下一步（按可靠性排序）

1. **定死 `task → vm_map` 的偏移**（这是唯一挡在"VM Map 有没有登记"前面的问题）。
   办法：拿一个**只有一个线程**的 task，或用 `LC_FUNCTION_STARTS` 索引挑出
   `vm_map_lookup` 一类的函数，从其反汇编里的 `ldr [xN, #imm]` 读出真实偏移。
2. 在能可靠读 vm_map 之后，对 117 个 stuck 页逐个查询 entry 是否存在、
   `protection` 是否为 NONE（guard）、`object` 是否为 pager-backed。
3. 修 `ptw` 诊断的 4 KiB/16 KiB 粒度问题，直接观察这些页的 PTE 有没有被写入过。
