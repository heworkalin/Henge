# 定位内核 VM 结构的一次可复现尝试（2026-11-17）

目标：确认"档案馆"（vm_map）在哪里，从而回答"卡住的页到底有没有被登记"。

## 1. 成功的一半：pmap 定位（可复现）

不猜偏移，从**已知值**出发：

1. 读 `hv_last_el0_ttbr0` = `0x70000eeea8000` → 页表基址 `0xeeea8000`、ASID `0x7`
2. 全 RAM 搜这个基址作为 u64 → **只有一个命中**，PA `0x8435aab8`
3. 该处上下文：`+0x18 = 0xfffffe001c226368`（内核代码指针）、
   `+0x20/+0x38/+0x40/+0x50 = 0xfffffe1e55f5xxxx`（内核堆）——
   这是 pmap 结构里存页表基址的位置
4. 反查它的 VA：遍历内核页表（`ttbr1 = 0x837f8000`）找出映射到该物理页的项，
   得到 `0xfffffe1e55f54000`（与上面那些 `0xfffffe1e55f54xxx` 指针完全吻合）
5. pmap 的 VA = `0xfffffe1e55f54000 + (0x8435aab8 − 0x84358000) = 0xfffffe1e55f56ab8`

**这条链是可复现的**：ttb0 值 → 唯一物理页 → 页表反查 → VA。

两个过程中的坑（都踩了）：

- 16 KiB granule 的索引位宽是 **L1/L2/L3 各 2048 项**，按 4 KiB 的 512 项算会漏掉一半；
- 页内偏移要先 `PA & ~0x3fff` 再相减，直接用低位会差 `0x2000`。

## 2. 没成功的一半：vm_map

尝试了三种特征，都被否掉：

| 特征 | 结果 |
|---|---|
| 指向 pmap 的指针 | 扫到 309 个，但上下文是 per-CPU 结构（含 `0xfffffe001c226440` 等函数指针） |
| `page_size == 0x4000` + 附近有 pmap 指针 | 12 个候选，第一个上下文里出现 **`0x000800226511a511`（正是 TCR）** → 是 CPU/TLB 状态结构，不是 vm_map |
| `{prev,next,start,end}` 形状 | 已证明不是 vm_map（见 `fault-retest-667pages-2026-11-17.md`：已映射页反而没有节点，且 prev 不回指） |

**结论：vm_map 仍未定位。** 因此"卡住的页有没有被登记"这个问题依然悬着。

## 3. 为什么这一步这么难

`task → vm_map` 的偏移一直没定死。此前试过的 `task+0x50`、`+0x58`、`+0x60` 全部被证伪
（指向线程链节点或线程链本身）。而**无符号的内核主代码**让"从函数反汇编读偏移"这条路
需要先解决函数定位（`LC_FUNCTION_STARTS` 只给边界，不给名字）。

## 4. 两条真正可行的下一步

**路径 A（最省事，直接回答现象）**：修 `ptw` 诊断的粒度问题（4 KiB → granule）。
它不改任何加载逻辑，只让现有诊断能看见 16 KiB 表项被写/被清。
这样即使不知道 vm_map 在哪，也能回答"PTE 到底有没有被写入过"，从而区分：
- 从没写过 ⇒ 内核决定不装（要查 vm_map/protection）
- 写了又被清 ⇒ 有人在回收（要查 pmap_remove 类路径）

**路径 B（彻底但要功夫）**：用字符串锚点定位内核函数。
`panic("vm_map_lookup ...")` 这类字符串在 `__LINKEDIT` 里，可以反查引用它的 `adrp/add`
点，从而找到函数入口，再从 `ldr [xN, #imm]` 读出 `task->map` 的真实偏移。
这一步纯离线（kernelcache 已在本地），但需要写一个字符串交叉引用工具。

## 5. 当前确定的事实清单（不依赖 vm_map）

- 708 页反复 fault（≥5 次），117 页全部 fault 在 offset 0
- 最典型页 `0x102614000`：136 次、单一地址、9 个 pc、横跨故障 #201→#16164
- fault 次数多的页至今 UNMAPPED，次数少的已映射
- ESR：`DFSC=7`（translation fault L3）、`EA=0`（非外部 abort）、`WnR=0`（读）
- 引擎 walk 与手工遍历一致；`TLB-fresh mismatch` = 0（40154 条 store）
- ramdisk 在内存，无块设备请求
