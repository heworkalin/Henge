# 已知问题：GPU 画面的三种故障（2026-11-21/22 记录，未修）

这一份记录 GPU 渲染的**三类**内容故障。它们外观不同，不要混为一谈：

| # | 外观 | 出现时机 | 记录日期 |
|---|---|---|---|
| A | 整屏**竖条纹**（横排文字被切成竖带） | 内容一变化就整屏变成条纹 | 11-21（`Screenshot_2026-11-21-23-44-03`，已 pull 核对） |
| B | **重复字形图块**铺满屏幕（本文件新的一节） | macOS "创建 Mac 账户" 界面 | 11-22（`docs/images/Screenshot_2026-11-22-03-06-57-42*.jpg`） |
| C | 局部区域**变黑** | 内容更新时偶发 | 11-22（`docs/images/Screenshot_2026-11-22-03-12-*.jpg`） |

三者的共同背景：**帧一直在到**（`guest presents` 持续增长），`PageFault`/`AccessRevoked` 为 0，
所以都不是"队列被吊销 / 零帧"那个已经修好的问题（`docs/gpu-pixels-2026-11-21.md`），
而是**内容或合成层面的错**。

## B：重复字形图块（`Screenshot_2026-11-22-03-06-57-42`）

现象：macOS 的"创建 Mac 账户"对话框正常布局（标题、字段、按钮位置都在），但**文字被替换成
重复的字形图块** —— 每个字符位置显示同一串 "H" 形图案；背景壁纸也变成网格状的同种图案。
HUD 读数：`CPU 100% / GPU 16% / FPS 23.7`。

形态判读：这是**纹理采样/图集（glyph atlas）**层面的错，不是位置错：

- 文字的每个字形都从同一张图集纹理采样；如果**图集的 UV 或 mip 级别算错**，
  就会退化成"重复同一个图块"；
- 背景也变成同一图案，说明**该图案所属的那块纹理被用在了所有采样上**，
  更像"绑定错了纹理"或"纹理内容/布局被覆盖"（例如我们的拷贝合并回把别的页写进了图集）。

最可能的方向（按成本）：

1. **纹理导入的内容**：`copied`/`host_memory` 路径下，我们把 guest 页拷进自己的映像再合并回；
   如果同一张图集的相邻 subresource 被分到不同的拷贝批次，批次之间可能互相覆盖 —— 打开
   `REIMS_DIAG=1` 看每次 completion 的 `offset/length` 是否重叠。
2. **tile/stride 假设**（与 A 同源）：`display present ... stride 15360`（= 1920×8）与我们按
   4 字节/像素解析不符；若 surface 实际是 8 字节/像素或两平面，图集内容会整体错位。
3. **mipmap/采样器**：`SamplerDescriptor` 的 `mipFilter`/`lodBias` 若被翻译成 Vulkan 的
   不同语义，图集会退化成低级别的一团。
4. **UBWC/tiled**：Adreno 的压缩布局未解（最贵，前三条排除后再做）。

## C：局部变黑（`Screenshot_2026-11-22-03-12-*`）

局部矩形区域在内容更新后变成纯黑（清屏色），其余正常。方向：局部更新的 rect 未覆盖、
或 clear 之后该区域没有被重绘（见前文的 `copied` 合并回范围）。

## A：竖条纹（保留原文）

- 不是"局部黑块"。整屏是**规则竖条纹**：原本横排的文字被切成一条条竖带，每带的字形是同一批
  内容的碎片，带与带之间周期性重复；
- 截图 HUD：`CPU 80% / GPU 6% / FPS 13.7` —— 帧率只有 ~14fps，瓶颈在 guest CPU（JIT），
  与"画面投递慢"的体感一致。

"竖条纹 + 周期性重复 + 内容碎片"是**行间距（pitch/stride）不匹配**的典型外观。佐证：
`display present #N: port 0 format 0x52476841 1920x1080 stride 15360`，`15360 = 1920 × 8`，
而 ARGB8888 应为 `7680`。

## 下次要抓的东西（不改代码就能区分）

| 想看什么 | 怎么做 |
|---|---|
| 是"guest 画的就是错的"还是"我们传错了" | `HV_GRAB_EVERY` 抓 `gpu-NNN.bmp`：抓到的图里也坏 = guest 侧/我们喂给 guest 的数据坏；抓到的好、屏幕上坏 = 上屏路径 |
| 拷贝批次是否互相覆盖 | `REIMS_DIAG=1` 看 `copied`/`host_memory` 的 `offset/length` 序列 |
| stride 的真实含义 | 在 present 处打印 `stride / bpp` 与 width 的比值，确认是否 2×（两平面/10bpc/交错） |
| 纹理绑定是否错 | 用单色背景的界面（Finder 窗口）复现，区分"图集坏"与"整块纹理错绑" |
